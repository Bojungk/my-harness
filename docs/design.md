# Sossbar 디자인 시스템 v2.3 — 적용 근거

> 2026-10-05 · 대상: 디자인·개발·기획 · 원본 문서: `sossbar-design-system.md`

## 결론

**접근성 위반 3건과 토큰 구조 모순 5건을 고쳤습니다. 브랜드 값은 건드리지 않았습니다.**

색·서체·Radius 상한 같은 브랜드 결정은 전부 유효합니다. 바꾼 것은 **측정으로 결함이 확인된 항목**뿐이고, 모든 변경은 WCAG 2.1 대비를 계산해 검증했습니다. 3겹 합성(텍스트 → 채움 → 표면)까지 포함해 **미달 0건**입니다.

기획 피벗(개인 평판 → 팀 회고)은 Foundation에 영향이 없습니다. 바뀌는 것은 화면 구성과 도메인 컴포넌트뿐입니다.

---

## 1. 접근성 위반 — 선택이 아니라 수정해야 할 것

측정값이 기준에 미달했으므로 취향 문제가 아닙니다.

| 항목 | 측정값 | 기준 | 조치 |
| --- | --- | --- | --- |
| 포인트 컬러 `#fe6237` + 흰 글자 | **2.99:1** | 4.5:1 (SC 1.4.3) | 채움용(`500`, 어두운 글자 5.93)과 텍스트용(`700`, 5.46)을 분리 |
| 경계선 `#cdd1d5` | **1.54:1** | 3:1 (SC 1.4.11) | 기능적 경계는 `gray/500`(4.83), 장식은 별도 토큰으로 분리 |
| 대비 등급 표기 | 측정 기준 불명 | — | 흰 글자 / 어두운 글자 **두 컬럼으로 분리** |

**포인트 컬러는 문서 안에서 이미 모순 상태였습니다.** 팔레트는 `500`을 포인트로 지정했지만, 같은 파일 5장에 "오렌지 600~900 구간이 접근성을 만족"이라고 적혀 있었습니다.

**대비 등급은 계산해보니 흰색·검정 중 유리한 쪽 기준이었습니다.** 그래서 `primary/300`(흰 배경에서 2.70, 탈락)과 `primary/700`(7.82)이 똑같이 "AAA"로 표기됐습니다. 디자이너에게 아무 지시를 못 주는 표기입니다.

**경계선은 램프 자체에 쓸 값이 없었습니다.** `gray/300`(1.47) · `gray/400`(2.54) 모두 3:1 미달이라 `gray/500`이 최소선입니다. WCAG는 선 두께로 면제해주지 않습니다.

## 2. 토큰 구조 — 지금 고치지 않으면 비용이 커지는 것

| 항목 | 문제 | 근거 |
| --- | --- | --- |
| `light` 접두사 제거 | `color/light/danger/50`은 **모드를 토큰 이름에 박아둔 것** | 다크모드 도입 시 전 토큰 리네임 + 전 작업파일 재링크 발생. 지금 Figma 모드 구조만 잡으면 값은 나중에 채워도 됩니다 |
| 번호 체계 단일화 | 라벨 `5~95`와 변수 `50~950`이 공존 | "primary 50"이 `#ecf0ff`인지 `#4164ff`인지 알 수 없음. 핸드오프 혼선 |
| `gray/1000` 제거 | `#1a1a1a`가 `#111827`보다 **밝음** (휘도 0.0103 vs 0.0092) | 램프 순서 역전. 전 계열이 블루그레이(B−R 22~24)인데 이것만 중성(B−R 0) |
| 본문색 교체 | `#1e2124`가 어떤 팔레트에도 없는 **고아 값** | 제품에서 가장 많이 쓰는 색이 참조 없는 리터럴. `gray/900`으로 교체 시 대비 16.18 → **17.74** 개선 |
| Radius 구조 분리 | 토큰 1개에 값 2개 (`Medium` = 6px **그리고** 8px) | 스케일과 "컨테이너 크기별 선택 가이드"를 한 표에 섞은 탓. 토큰은 단일 값이어야 함 |

**다크모드 지원 여부와 네이밍은 하나의 결정입니다.** 따로 보고 있었지만, `light`를 이름에 남긴 채 다크모드를 미루면 나중에 전면 리네임이 발생합니다.

## 3. 타이포그래피 — 품질과 중복 문제

| 항목 | 변경 | 근거 |
| --- | --- | --- |
| Detail 계열 삭제 | → Caption 1개로 흡수 | Body와 크기가 **네 단계 전부 동일**(20/19, 16/17, 14/15, 12/17). 구별 불가능한 두 패밀리를 용도로만 나눈 상태. 위계는 크기와 색으로 만듭니다 |
| 행간 150% 고정 해제 | → 구간별 곡선 | 56px × 1.5 = **84px**. 큰 글자는 광학적으로 조여야 합니다. **본문 16px는 24px로 변화 없음** |
| 본문 weight 500 → 400 | | 본문이 500이면 강조가 700뿐이라 점프가 크고, 400은 사실상 사장됩니다. 권장 사다리는 본문 400 / 강조 500 / 강조강 700 |
| Display 자간 +0.8px → −1.5% | | 디스플레이 타입은 음수 자간이 표준. Pretendard는 기본 자간이 넉넉해 큰 사이즈에서 +자간을 주면 흩어져 보입니다 |
| 모바일 크기 2건 조정 | 32→36, 28→32 | 모바일 28px에 **3개 스타일이 충돌**(Display small / Heading xxlarge / xlarge). 2개 값 변경으로 해소 |
| `xsmall` 모바일 17px → 13px | | PC→모바일 규칙이 "20px↑ 축소 / 16px↓ +1px 확대"로 **12개 중 11개 일관**. xsmall만 +5px로 유일한 위반 |

## 4. Opacity 토큰 도입 — 배경 독립성 확보

불투명 단색은 배경마다 변형 토큰이 필요합니다. 반투명은 흰 배경·구분 배경·카드 위 어디에 올려도 아래 색과 섞입니다.

**단, 알파는 배경 레이어에만 적용했습니다.** 텍스트와 기능적 경계는 불투명으로 유지합니다.

- `border/functional`을 알파로 전환하면 3:1을 넘기는 최소 스텝이 **opacity-88**입니다. 거의 불투명이라 의미가 없습니다.
- 반투명 텍스트 × 반투명 채움은 대비가 누적 하락합니다. 전환해 검증했더니 `fill/strong` 위에서 **4.28~4.50 미달**이었습니다.

## 5. 컴포넌트를 기획 확정 전에 착수하는 이유

피벗이 바꾸는 것은 **화면 구성과 도메인 컴포넌트**입니다. 기본 프리미티브는 어느 쪽이든 동일합니다.

| 피벗 무관 — 지금 착수 | 피벗 영향 — 기획 확정 후 |
| --- | --- |
| Button · Text Input · Textarea · Select · Checkbox · Radio · Switch · Badge · Tag · Chip · Dialog | Card 종류 · Avatar 구분 · 상태 배지 라벨 · 참여 현황 UI |

**착수 0순위는 컴포넌트가 아니라 Figma Variables 연결입니다.** 위 2장의 결함(램프 역전, 고아 값, 값 불일치)이 지금까지 발견되지 않고 남아 있었던 이유가 토큰이 변수로 묶이지 않았기 때문입니다. 변수 없이 컴포넌트를 만들면 하드코딩된 색이 수백 개 생깁니다.

## 6. 바꾸지 않은 것

| 항목 | 상태 |
| --- | --- |
| Primary · Secondary · 상태색 3종의 `500` 기준값 | 계산해 AA 통과 확인 후 **그대로 유지** (4.56 ~ 5.14) |
| 팔레트 Hex 78개 | 원본 그대로 |
| Pretendard · 3단 weight · 타이포 계열 구조 | 유지 |
| Gray = Tailwind 채택 결정과 선정 근거 | 유지 |
| Radius 2~16 범위와 최대 16px 상한 근거 | 유지 (KRDS·Tailwind 절충) |
| 피벗 영향 4분류 | 유지 |

색 중 손댄 것은 Tertiary 하나뿐이고, 2.99:1이라 불가피했습니다.

## 7. 검증 방법

`.fig`/스타일 가이드 값을 직접 읽어 **WCAG 2.1 상대 휘도 공식으로 전 조합을 계산**했습니다. 추정값은 없습니다.

| 검증 범위 | 건수 | 결과 |
| --- | --- | --- |
| 팔레트 78색 × 흰 글자 / 어두운 글자 양방향 | 156 | 전 스텝 권장 용도 산출 |
| 시맨틱 토큰 조합 (Light / Dark) | 26 | 미달 0 |
| 3겹 합성 — 텍스트 → 채움 → 표면 | 33 | 미달 0 |

## 남은 항목

승인으로 해결되는 항목은 모두 처리됐습니다. 남은 것은 외부 입력이 필요한 것뿐입니다.

- **Figma 원본 필요** — 간격 스케일(역산 가설) · Primary 테두리 `#d8e5fd` · 그래픽 컬러 · Shadow 원본 실값

- **정의 작업** — 포커스 링(가장 시급) · 터치 타깃 · 모션 감소 · 색 외 상태 전달
